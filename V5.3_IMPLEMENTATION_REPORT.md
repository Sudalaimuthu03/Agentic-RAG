## Implemented root-cause fixes

### 1. Authoritative conversation state

Extended `ConversationState` with:

- candidate targets
- comparison set
- last successful target
- last successful target set
- last operation
- last topic
- last evidence
- pending clarification
- unresolved reference

Clarification turns no longer erase the last successful target.

### 2. Deterministic verification/reference binding

Verification references now bind to the active authoritative target set rather than an arbitrary historical resolution.

Collective references such as `both` can use pending clarification candidates/current candidate sets instead of stale historical targets.

### 3. Durable clarification state

Clarification candidates are retained in authoritative state. A follow-up such as `for hospital` resolves the pending clarification instead of starting an unrelated interpretation.

### 4. Retrieval-before-refusal

Execution planning now distinguishes true closed-world unknowns from requests for which bounded indexed candidates exist. Plausible indexed requests can reach retrieval before refusal.

### 5. Target satisfaction / wrong-target protection

The execution/evidence pipeline continues to require alignment between resolved target and evidence source. Answer validation now also rejects known evidence that is outside an explicit resolved document scope.

### 6. Validation enforcement

If final answer validation fails, the system attempts a bounded repair and re-validates. If validation still fails, the original factual answer is not released; a controlled evidence limitation is returned instead.

### 7. Generic candidate discovery robustness

Candidate discovery received a small domain-independent singular/plural normalization so generic topics such as `complaints` can match corpus text containing `complaint` without adding domain-specific routing.

### 8. Release/version hygiene

Runtime version updated to `5.3.0`.
